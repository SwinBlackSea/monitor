# 极简多机进程监视器 — 产品说明书

> 版本：v3.0<br>
> 状态：当前实现基线<br>
> 更新日期：2026-07-28<br>
> 本文只描述产品行为；实现、接口和部署细节见 `TECHNICAL_DESIGN.md`。

## 1. 产品定义

这是一个面向少量可信 Linux 机器的轻量 Web 进程监视器。产品参考 macOS「活动监视器」的使用方式，以机器 Tab、资源 Tab 和一张可排序表格为核心，不做复杂仪表盘。

用户打开页面后可以：

- 在顶部切换机器。
- 查看当前机器 CPU 或内存占用最高的进程。
- 查看挂载点和逐级展开的目录占用。
- 在明确确认后终止进程或清空指定目录内容。
- 直接在页面新增、测试、编辑、重命名和删除机器。

## 2. 设计原则

1. **极简**：纯白背景、中性灰分隔线、克制的状态色，不使用渐变、插画、大卡片或装饰图表。
2. **列表优先**：资源信息集中在表格中，打开即可看到最重要的数据。
3. **即时反馈**：资源切换先显示缓存；终止进程、添加或删除机器先更新当前界面，再与后端确认。
4. **位置稳定**：刷新时保持页面结构、滚动位置和字段位置稳定，避免跳动。
5. **风险明确**：终止进程与清空目录都必须二次确认，危险功能默认关闭。

## 3. 页面信息结构

```text
进程监视器
├── 机器 Tab：SSH 连通状态点 + 机器名称 + 编辑入口
├── 当前机器访问地址
├── 资源 Tab：CPU / 内存 / 硬盘
├── 三个固定位置的资源摘要
├── CPU/内存专属：资源采集状态点 + 采集时间
├── 可排序表格或硬盘目录树
└── 当前数量与刷新说明
```

页面没有重复的“连接正常”“在线”等状态文字。机器 SSH 连通性和当前资源采集结果使用两套独立状态点。

## 4. 机器 Tab 与机器管理

### 4.1 Tab 规则

- 有几台机器就展示几个 Tab。
- Tab 名称来自机器配置，支持重命名。
- 首次打开页面默认选择第一台机器和 CPU。
- 第一次进入其他机器时默认打开 CPU。
- 每台访问过的机器记住自己最后打开的 CPU、内存或硬盘页面；切走再回来时恢复该页面。
- Tab 超出宽度时横向滚动，不折行。
- 当前 Tab 使用浅灰底和底部短线，其他 Tab 保持白底。

### 4.2 SSH 连通状态点

| 颜色 | 含义 |
|---|---|
| 绿色 | 最近一次轻量 SSH 检测成功 |
| 黄色 | 首次检测中、首次失败正在复查，或结果超过 75 秒未更新 |
| 红色 | 连续两次轻量 SSH 检测失败 |

- 三种状态点都有轻微心跳效果。
- 每个机器 Tab 在名称前显示一个 SSH 连通状态点。
- 后端每 30 秒并行检测全部机器；远程机器只执行 `ssh ... true`，不采集资源。
- 首次失败保持黄色，约 3 秒后复查；复查仍失败才变红。
- 任意一次检测成功立即恢复绿色。
- 本机配置不建立 SSH，监视器进程运行时视为可达。
- 浏览器每 30 秒读取一次后端状态缓存，不直接执行或触发 SSH。
- 状态缓存保留到覆盖、删除机器或服务重启；超过 75 秒未更新时对外显示黄色。
- 关闭动画偏好时停止心跳动画。

### 4.3 添加和编辑

机器表单包含：

- 机器名称
- IP 地址或主机名
- SSH 用户
- SSH 端口

交互要求：

- “测试连接”和“保存”是两个独立操作。
- 测试连接只验证当前输入，不保存配置。
- 保存负责提交配置；新增或修改连接参数时，后端会在落盘前验证连接。
- 测试结果在表单中的独立轻量区域展示。
- 输入框聚焦时只有一层清晰边框。
- 页面不接收或保存 SSH 密码、私钥。
- 新增成功后立即出现新 Tab、切换到新机器并展示首次快照。
- 编辑名称后 Tab 立即更新。

### 4.4 删除机器

- 删除前弹出确认框。
- 删除只移除监控配置，不修改或关闭远程服务器。
- 删除当前机器后优先返回上一台访问过且有缓存的机器。
- 删除请求发出后 Tab 立即消失；失败时完整恢复。
- 至少保留一台机器。

## 5. 地址显示

地址只在机器 Tab 下方展示一处，不重复显示状态点：

| 场景 | 显示 |
|---|---|
| 监控程序所在本机 | 浏览器实际访问的主机名或 IP |
| 普通远程 SSH | 配置的 SSH IP 或域名 |
| 非本机且 SSH 地址为回环地址 | 优先显示识别到的反向隧道公网对端 |
| 反向隧道识别失败 | 显示配置的回环地址和 SSH 端口 |

反向隧道识别必须只作用于“非本机 + 回环地址”场景，不能改变普通 SSH 地址的展示。

## 6. 资源摘要与时间

三个资源摘要字段使用紧凑固定栅格。字段之间不显示分隔线；同一资源页刷新时保留字段节点和起始位置，只更新数值。

| 页面 | 摘要 1 | 摘要 2 | 摘要 3 |
|---|---|---|---|
| CPU | CPU 总占用 | 系统负载 | 逻辑核心 |
| 内存 | 已用内存 | 进程数量 | 逻辑核心 |
| 硬盘 | 已用空间 | 可用空间 | 总容量 |

CPU 和内存页面只在“逻辑核心”后继续展示采集时间。

时间规则：

- 采集时间前显示当前机器资源采集状态点：绿色为最近采集成功，黄色为尚未采集，红色为最近采集失败。
- 资源采集状态只来自当前机器快照，不使用 SSH 健康缓存。
- 采集时间字体与摘要一致，间距紧凑，不放大。
- 采集时间的两个冒号每秒轻微跳动。
- 不使用延迟红字或悬停提示。
- 硬盘页面不展示采集时间。

## 7. CPU 页面

### 7.1 默认行为

- 展示当前快照中的全部进程。
- 默认按 CPU 占比从高到低排序。
- 每个数据列均可点击排序，再次点击切换升降序。
- 表格正文使用常规字重，不加粗。

### 7.2 列

| 列 | 内容 |
|---|---|
| 进程名称 | 可执行程序或服务名称 |
| 父进程 | 父进程名称和父 PID |
| 用户 | 进程所属系统用户 |
| PID | 进程 ID |
| 线程 | 线程数量 |
| CPU | 进程 CPU 百分比 |
| 操作 | 终止按钮 `×` |

## 8. 内存页面

### 8.1 默认行为

- 与 CPU 使用同一份已采集快照，点击后立即显示，不等待新请求完成。
- 默认按内存占比从高到低排序。
- 切换后可以在后台刷新当前机器，但不得先清空表格。
- 每个数据列均支持升降序排序。

### 8.2 列

| 列 | 内容 |
|---|---|
| 进程名称 | 可执行程序或服务名称 |
| 父进程 | 父进程名称和父 PID |
| 用户 | 进程所属系统用户 |
| PID | 进程 ID |
| 常驻内存 | RSS，自动使用 KB/MB/GB/TB |
| 内存占比 | 进程内存百分比 |
| 操作 | 终止按钮 `×` |

## 9. 终止进程

- 只在 CPU 和内存页面显示 `×`。
- PID 1、监视器自身等关键进程不可终止。
- 点击 `×` 后必须确认，不直接执行。
- 确认框显示机器、进程名称和 PID。
- 确认后立即从当前机器的 CPU 与内存缓存中移除该进程。
- 后端执行成功后快速重新采集当前机器，更新 CPU、内存与摘要。
- 失败时恢复缓存并展示错误。
- 未使用 `--allow-kill` 启动时，终止接口不可用。

## 10. 硬盘与目录树

### 10.1 挂载点

- 初始展示持久化挂载点，排除 `tmpfs` 和 `devtmpfs`。
- 默认按使用率从高到低排序。
- 目录、占用空间和占挂载点比例三列均支持排序。
- 挂载点行不显示终止进程按钮。

### 10.2 逐级展开

- 点击挂载点后查询其直接子目录。
- 点击子目录可继续逐级展开，不限制展示深度。
- 每个目录显示递归占用空间和占所属挂载点比例。
- 用户主目录使用 `~/` 缩写，例如 `/home/ubuntu` 显示为 `~/`。
- 查询期间只显示稳定的加载行。
- 后端所有并行统计任务完成后，统一排序并一次性显示结果，不分批插入导致顺序变化。
- 收起任一目录时，其所有后代同时收起；再次展开仍使用浏览器已取得的数据。

### 10.3 查询与缓存

- 硬盘页面没有 5 秒自动刷新。
- 只有点击目录时才查询该目录。
- 后端按“机器 + 挂载点 + 路径”缓存目录结果 10 分钟。
- 命中后端缓存时直接返回；未命中时启动一次后台任务。
- 浏览器已取得的目录数据继续保留，不要求在 10 分钟到期时强制删除。
- 目录任务执行期间，前端只轮询同一个任务接口，不为每个子目录分别发请求。
- 后台 CPU/内存采集不得重建硬盘表格 DOM、改变展开状态或引起页面抖动。
- 远程扫描只统计与当前目录属于同一文件系统的直接子目录，不能在扫描 `/` 时继续进入 `/proc`、`/dev`、`/sys` 等其他挂载。
- 个别子目录权限不足时，保留其余可读取结果，并在当前树内显示具体路径与原因，例如“无法读取 /home/lighthouse：Permission denied”；SSH 连接失败则明确显示为 SSH 连接错误。
- 页脚显示“点击目录时查询 · 结果缓存 10 分钟”。

### 10.4 清空目录

- `--allow-delete N` 配置从挂载点下第 N 级开始允许清空，且 `N ≥ 3`。
- 裸写 `--allow-delete` 兼容为 `--allow-delete 3`。
- 只有第 N 级及更深目录显示清空按钮 `×`。
- 未使用 `--allow-delete N` 启动时，默认从第 3 级显示禁用按钮和稳定的自定义提示。
- 提示不得因为页面刷新而重复弹出。
- 点击后必须确认，并明确说明“清空内容、保留目录本身、无法撤销”。
- 执行时只删除目标目录内部内容，不删除目标目录。
- 不跨越挂载点，不允许通过路径或符号链接逃逸。
- 成功后目标目录继续显示，占用更新为 0，并清理相关目录缓存。
- 权限不足或目录不可读时，在对应树位置显示可读错误，不破坏其他已加载分支。

## 11. 采集、切换与缓存体验

- 页面只持续采集当前选中的机器。
- 后端对全部机器执行的 30 秒轻量 SSH 健康检查不属于资源采集。
- CPU/内存页面默认每 5 秒请求一次当前机器；后端按机器共享同一份 5 秒快照。
- 多个浏览器同时查看同一台机器时，同一有效期内直接返回内存快照；快照过期后只执行一轮采集，其余请求等待并复用该结果。
- 多个浏览器查看不同机器时，各机器可以独立并行采集，不因此扫描未被查看的机器。
- 未选中的机器不建立新的周期采集连接。
- 切走后保留该机器最后一份浏览器缓存和后端内存快照。
- 切回时先立即展示上次缓存，再只刷新当前机器。
- 从未访问的机器首次进入时显示加载状态，采集完成后展示。
- 同一轮只请求一个当前机器快照接口，不重复查询机器元数据。
- CPU/内存切换可以立即请求刷新，但快照仍有效时不会重复执行 SSH、`ps` 或 `df`。
- 终止进程、清空目录或修改 SSH 连接后，对应机器快照立即失效，并在受控刷新中重新采集。
- 页面切到浏览器后台时暂停周期采集。
- 刷新后仍按当前资源占比降序，并使用轻量行移动或数值变化动画。
- 硬盘目录结果不参与 5 秒周期采集。

## 12. 视觉与响应式

### 12.1 桌面

- 内容最大宽度约 1180 px，居中。
- 背景纯白，边框浅灰，文字使用系统字体。
- 不使用大面积状态色、阴影卡片、渐变、插图或 PNG 装饰。
- 表格行高紧凑但可读，数字采用等宽数字特性并右对齐。
- `×` 默认中性灰，悬停时使用浅红反馈。

### 12.2 移动端

- 机器 Tab 横向滚动。
- CPU/内存/硬盘三个资源 Tab 始终完整可见。
- 隐藏次要列，将 PID 与父进程信息补充到进程名下方。
- 保留核心指标和操作按钮。
- 页面不得产生整体横向滚动。

### 12.3 可访问性

- Tab、表头和按钮提供可读标签与键盘焦点态。
- 状态点同时有机器状态语义，不能只依赖装饰。
- 危险按钮具有明确的 `aria-label`。
- 支持 `prefers-reduced-motion`。

## 13. 安全与访问边界

- 服务默认只监听 `127.0.0.1`。
- 监听非本机地址时必须配置 Web 基础认证。
- 域名访问建议通过 Caddy/Nginx 或可信 VPN 提供 HTTPS。
- 程序自身只提供 HTTP，不负责 TLS 证书。
- SSH 使用运行 `monitor.py` 的系统账户和已有密钥，不在网页存储 SSH 凭据。
- 终止进程与清空目录分别由 `--allow-kill`、`--allow-delete N` 显式开启。
- 目录清空能力应只授予可信管理员。

## 14. 数据保留

| 数据 | 是否持久化 |
|---|---|
| 机器配置 | 是，写入当前启用的机器配置文件 |
| CPU/内存/挂载点快照 | 否，只保留内存中的每机最新值 |
| 目录占用结果 | 否，后端内存缓存 10 分钟 |
| 浏览器目录树 | 否，保留到页面刷新或主动失效 |
| 历史趋势与审计数据库 | 不提供 |

服务重启后，机器配置仍在；快照和目录缓存重新按需生成。

## 15. 不在当前范围

- 历史趋势、图表、告警和容量预测。
- 多用户角色、细粒度权限和审计查询。
- 容器指标、日志、链路追踪和 APM。
- Windows/macOS 目标机器。
- Agent 安装与中心数据库。
- 严格等同 `top` 采样窗口的瞬时进程 CPU。

## 16. 验收标准

- 机器数量与顶部 Tab 数量一致，支持新增、测试、保存、重命名和删除。
- 未访问机器不采集；切换后只请求当前机器。
- 每个机器 Tab 展示独立 SSH 连通点；浏览器只读取 `/api/host-statuses` 缓存，不触发 SSH。
- SSH 状态遵循 30 秒检测、首次失败 3 秒复查、75 秒未更新变黄的规则。
- 切回已访问机器立即显示缓存，再原位刷新。
- CPU、内存默认降序，所有数据列可排序，父进程完整展示。
- CPU/内存切换立即显示，刷新不闪白、不清空。
- 10 个浏览器同时查看同一台机器时，每个采集周期最多执行一次实际资源采集；并发请求返回同一轮快照。
- 三个摘要字段在三个资源页面位置稳定、间距紧凑且无分隔线，同页刷新只更新数值。
- 采集状态点只位于 CPU/内存采集时间前，并与机器 Tab 的 SSH 状态逻辑独立。
- CPU/内存可以确认后终止进程，硬盘挂载点没有进程终止按钮。
- 硬盘只在点击目录时查询，目录结果缓存 10 分钟，展开树不因后台采集抖动。
- `--allow-delete N` 的 N 至少为 3；第 N 级及更深目录可在确认后清空内容，并始终保留目标目录本身。
- 反向隧道只在对应场景识别公网地址，不影响普通 SSH。
- 390 px 宽度无页面级横向溢出。
- 自动化后端测试和 Chromium 浏览器回归全部通过。

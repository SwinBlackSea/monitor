# 极简多机进程监视器 — 技术方案

> 版本：v3.0<br>
> 状态：当前实现基线<br>
> 更新日期：2026-07-30<br>
> 产品行为与验收口径见 `PRD.md`。

## 1. 技术目标

在不引入 Python 第三方依赖、数据库、前端构建链和目标机 Agent 的前提下，提供多机进程监控、按需目录统计及受控运维操作。

核心取舍：

- 一个 Python 进程。
- 一个 Python 后端文件 `monitor.py`。
- 一个原生前端文件 `index.html`。
- Python 标准库 `ThreadingHTTPServer`。
- 目标机通过系统 `ssh` 访问。
- 机器配置写入 JSON；监控快照和目录结果只在内存保存。
- 只周期采集当前浏览器页面选中的机器。

## 3. 总体架构

```text
浏览器（原生 HTML/CSS/JavaScript）
        │ HTTP/HTTPS
        ▼
monitor.py
├── ThreadingHTTPServer
├── Basic Authentication
├── 当前机器配置文件原子持久化
├── 每机最新快照内存字典
├── 每机 SSH 健康状态内存字典
├── 目录 KV 缓存与后台任务
├── 反向隧道地址缓存
└── subprocess
    ├── 本机：ps / df / du / /proc
    └── 远程：系统 ssh
             └── Linux：ps / df / du / /proc
```

目标机器不安装 Agent。浏览器也不直接连接目标机器，所有 SSH 与文件操作都由运行 `monitor.py` 的系统账户执行。

## 4. 运行生命周期

### 4.1 启动

1. 解析命令行参数和认证环境变量。
2. 优先从指定 `--hosts` 路径加载机器配置；未指定时优先读取同目录、被 Git 忽略的 `hosts.local.json`，不存在时读取已脱敏的 `hosts.json`。
3. 启动维护线程，只负责清理过期目录缓存和隧道地址缓存。
4. 启动 SSH 健康线程，立即对全部机器执行一次轻量连通检查。
5. 启动 `ThreadingHTTPServer`。
6. 启动阶段不采集全部机器的资源快照。

启动参数口径：

| 参数 | 默认值 | 技术含义 |
|---|---|---|
| `--bind` | `127.0.0.1` | HTTP 监听地址；监听非本机地址时强制要求 Web 认证 |
| `--port` | `8080` | HTTP 监听端口，范围 1–65535 |
| `--interval` | `5` | 浏览器资源请求周期及后端每机共享快照有效期，最小 1 秒 |
| `--hosts` | 自动选择 | 显式指定机器配置文件 |
| `--demo` | 关闭 | 使用内置模拟机器，不执行真实采集 |
| `--allow-kill` | 关闭 | 开启进程 SIGTERM 接口 |
| `--allow-delete N` | 关闭 | 从第 N 级开始允许清空目录内容，N ≥ 3 |
| `--username` / `--password` | 环境变量 | HTTP Basic Authentication 凭据 |

认证环境变量为 `MONITOR_USERNAME`、`MONITOR_PASSWORD`。命令行参数优先于环境变量，但生产运行推荐环境变量，避免凭据直接出现在进程命令行。

### 4.2 首次打开页面

1. 浏览器请求 `GET /api/hosts`，只读取机器元数据和已有缓存状态。
2. 前端选中第一台机器。
3. 浏览器请求 `GET /api/hosts/{id}/snapshot`。
4. 后端先检查该机器共享快照；仍在 `--interval` 有效期内则直接返回，否则取得该机器采集锁后执行一轮采集。
5. 前端使用同一快照渲染 CPU、内存与挂载点缓存。
6. 若首次 `/api/hosts` 临时失败，`hostId` 保持为空；下一次资源周期重新请求机器列表，成功选中机器后再恢复只请求当前机器。
7. `pageshow` 与 `visibilitychange` 触发页面恢复刷新；共享 Promise 和 500 ms 窗口将相邻事件合并，避免重复请求。
8. `apiUrl()` 从页面地址解析同源 API URL，并显式清空 `username/password`；Basic Auth 继续由浏览器认证会话处理，`fetch` 参数本身不携带 userinfo。

### 4.3 周期采集

- CPU/内存页面按后端 `/api/hosts` 返回的 `snapshot_interval_seconds` 请求当前机器 `/snapshot`，默认 5 秒。
- `--interval` 同时设置浏览器请求周期和后端每机快照有效期，最小 1 秒。
- 页面隐藏时停止周期请求。
- 硬盘页面不运行 5 秒快照轮询。
- 未选中的机器不产生新的周期采集。
- 多个独立浏览器页面各自拥有当前机器，但共享后端 `data`、单调采集时间和每机采集锁。
- 同一机器的快照仍有效时所有请求直接读内存；过期后的首个请求负责采集，其他并发请求等待同一个锁，随后复用新快照。
- 每机锁彼此独立，因此不同机器可以并行采集；机器数量和浏览器数量都不会触发全机轮询。
- 失败快照同样保留一个采集周期，避免连接异常时多个浏览器形成 SSH 重试风暴。

### 4.4 主机连通检查

- 后端健康线程每 30 秒复制一次机器列表并并行检测。
- 远程机器执行 `ssh -o BatchMode=yes -o ConnectTimeout=3 -o ConnectionAttempts=1 ... true`，总超时 4.5 秒。
- 本机配置不执行 SSH，直接视为可达。
- 首次失败写入 `warning`，等待 3 秒后只复查首次失败的机器；再次失败写入 `offline`。
- 任意成功将状态写为 `normal` 并清零连续失败次数。
- 每机 KV 只保存最新状态、检测时间、连续失败次数、检测中标记和最近错误。
- KV 不按 TTL 删除；状态超过 75 秒未更新时，接口派生返回 `warning`。
- 删除机器时删除对应 KV；修改 SSH 连接信息后重置为未检测；服务重启后从黄色开始。
- 每个探测结果携带发起时的连接字段快照；地址、用户、端口或本机标记已变化时丢弃迟到结果。

### 4.5 切换机器

1. 前端保留旧机器缓存和最后资源页面。
2. 如果新机器已有浏览器缓存，立即渲染该缓存。
3. 同时只请求新机器快照。
4. 使用递增请求令牌丢弃迟到的旧响应，避免覆盖新机器。
5. 后端仍保留所有访问过机器的最后快照，直到删除机器或服务重启。

### 4.6 切换 CPU/内存

CPU 和内存共享同一快照，因此切换时先同步渲染缓存，不等待网络。切换后允许发起一次当前机器刷新；后端快照仍有效时只返回内存数据，不重复执行 SSH。

## 5. 机器配置与管理

### 5.1 配置结构

```json
{
  "hosts": [
    {
      "id": "local",
      "name": "本机",
      "address": "127.0.0.1",
      "port": 22,
      "local": true
    },
    {
      "id": "server-1",
      "name": "生产服务器",
      "address": "10.0.0.8",
      "user": "monitor",
      "port": 22,
      "local": false
    }
  ]
}
```

持久化字段只有 `id`、`name`、`address`、`user`、`port` 和 `local`。Web 登录密码、SSH 密码、私钥和快照均不写入配置文件。

### 5.2 校验

- 机器名称：1–40 个字符。
- 地址：只接受 IP、主机名及必要的 IPv6 字符，不允许以 `-` 开头。
- SSH 用户：符合常见 Linux 用户名格式。
- SSH 端口：1–65535。
- 新增机器前进行一次采集验证，失败则不保存。
- 修改地址、用户或端口时重新验证；只重命名时不强制采集。

### 5.3 持久化

- 保存时先写当前配置文件对应的 `.tmp` 临时文件，再以原子替换更新当前配置文件。
- 写入失败时恢复内存中的旧配置。
- 测试连接接口不写文件。
- 删除机器同时删除其快照、目录缓存和目录任务。
- 至少保留一台机器。

## 6. 快照采集

### 6.1 远程单连接命令

每轮远程快照通过一次 SSH 执行固定命令，依次读取：

```text
ps -eo pid,ppid,user,comm,nlwp,pcpu,rss,pmem,lstart
df -PT -B1（排除 tmpfs、devtmpfs）
/proc/loadavg
nproc
/proc/meminfo 的 MemTotal、MemAvailable
$HOME
```

SSH 参数：

- `BatchMode=yes`
- `ConnectTimeout=3`
- 快照子进程总超时 4.5 秒
- 使用配置的 SSH 用户和端口

本机采集使用同等数据源；`ps` 与 `df` 子进程超时为 8 秒。

### 6.2 进程解析

每条进程记录包含：

- PID、父 PID
- 用户、命令名
- 线程数
- `%CPU`
- RSS 字节数
- `%MEM`
- 启动时间文本
- 根据同一快照 PID 映射得到的父进程名称

后端返回当前 `ps` 中的全部进程，不截断 Top 20。排序在浏览器中完成。

### 6.3 指标口径

| 指标 | 计算方式 |
|---|---|
| 进程 CPU | `ps %CPU`，通常是进程生命周期平均值 |
| CPU 总占用 | 当前进程 `%CPU` 之和除以逻辑核心数 |
| 进程内存 | `ps RSS` 与 `%MEM` |
| 整机已用内存 | `1 - MemAvailable / MemTotal` |
| 系统负载 | `/proc/loadavg` 的 1 分钟值 |
| 逻辑核心 | `nproc` 或本机 `os.cpu_count()` |
| 文件系统 | `df -PT -B1` |

当前实现不做两次 `/proc/{pid}/stat` 差分，因此进程 CPU 与 `top` 的瞬时采样窗口可能不同。

### 6.4 采集失败

- 异常会将该机器本轮状态标记为 `offline`。
- 如果该机器已有快照，保留上次进程、文件系统和摘要，只更新状态、时间和错误。
- 未采集机器状态为 `warning`。
- 成功采集状态为 `normal`。
- 当前实现没有“连续失败三次才离线”的计数器。

## 7. 内存状态与缓存

### 7.1 每机最新快照

```python
data = {
    "host-id": {
        "status": "normal",
        "updated_at": 1785240000000,
        "error": None,
        "home_path": "/home/ubuntu",
        "summary": {...},
        "processes": [...],
        "filesystems": [...]
    }
}
```

- 每台访问过的机器只有一个值，新采集直接覆盖旧值。
- `snapshot_collected_at[host_id]` 使用 `time.monotonic()` 保存成功或失败采集的后端时间，不依赖可被界面操作修改的 `updated_at`。
- `snapshot_generation[host_id]` 用于使终止进程、清空目录、修改连接或删除机器期间迟到的采集结果失效。
- `snapshot_locks[host_id]` 只串行化同一机器；请求进入锁后再次检查缓存，形成 single-flight 合并。
- 不累计历史记录，运行时间不会导致快照列表无限增长。
- `--interval` 只控制多久允许再次实际采集，不删除旧快照；只要服务运行且机器未删除，就保留最后值。
- 服务重启后全部快照清空。

### 7.2 浏览器缓存

前端 `state.cache` 同样按机器保存一份最新快照，用于机器和资源 Tab 的即时切换。缓存只存在于当前页面内存，刷新页面后重新获取。

### 7.3 目录 KV 缓存

键：

```text
(host_id, mount, path)
```

值：

```text
(写入时间, 完整目录结果)
```

- TTL 为 600 秒。
- 维护线程定期删除过期项。
- 清空目录或修改机器连接时，使该机器全部目录缓存失效。
- 浏览器中的目录树不按 TTL 强制删除。

### 7.4 隧道地址缓存

键为 `(address, port)`，TTL 同为 600 秒。普通 SSH 地址不进入检测流程。

## 8. 硬盘目录统计

### 8.1 请求模型

1. 前端点击目录，调用一次目录接口。
2. 命中缓存时立即返回完整结果。
3. 未命中时创建一个后台任务并返回 `pending: true`。
4. 前端每 900 ms 轮询同一个目录接口。
5. 所有子目录统计完成后，后端统一排序、一次性写入缓存并返回。

前端不会为四个工作线程分别调用四次接口。

### 8.2 本机统计

1. 使用 `os.scandir` 枚举直接子目录，不跟随符号链接。
2. 最多四个线程并行执行：

```bash
du -0 -x -B1 -s -- <直接子目录>
```

3. 每个 `du` 最长运行 300 秒。
4. 所有线程结束后按占用降序统一返回。

### 8.3 远程统计

远程通过一次 SSH 命令完成路径校验、同设备过滤和最多四路统计。核心逻辑为：

```text
target_dev = stat(<目录>).device
find <目录> -xdev -mindepth 1 -maxdepth 1 -type d -print0
| xargs -0 -r -n 1 -P 4 {
    child_dev = stat(<直接子目录>).device
    child_dev == target_dev && du -0 -x -B1 -s -- <直接子目录>
  }
```

- `readlink -f` 解析挂载点和目标路径。
- 校验目标目录仍在挂载点内。
- 目标路径必须可读且可进入，否则返回包含目标路径的 `Permission denied`。
- `find -xdev` 只限制遍历过程，但仍可能列出 `/proc`、`/dev`、`/sys` 等直接子挂载点；因此必须再比较设备号，避免把这些挂载点作为新的 `du` 根目录扫描。
- 单个子目录权限不足时解析标准错误，保留其他成功结果，并返回形如“无法读取 /etc/ssl/private：Permission denied（另有 48 处无法读取），当前占用结果可能不完整”的警告。
- 没有任何可用结果时返回具体错误；SSH 退出码 255 单独映射为“SSH 连接失败”，不与目录权限问题混淆。
- 所有诊断仅随当前请求返回，不写日志文件或持久化存储。
- 总超时 300 秒。

### 8.4 顺序与页面稳定

- 后端在任务完成前不返回部分目录行。
- 完成后统一按大小和名称稳定排序。
- 若只有部分子目录不可读，完整的可读结果与一条轻量内联警告一次性返回；前端不弹全局错误，也不丢弃已加载分支。
- 5 秒快照采集不调用硬盘表格渲染。
- 展开、滚动和 DOM 节点在非目录操作期间保持不变。

## 9. 清空目录

### 9.1 开关和深度

- 默认关闭，使用 `--allow-delete N` 开启；N 必须为不小于 3 的整数。
- `--allow-delete` 未显式给出 N 时按 3 处理，兼容已有启动命令。
- 只允许挂载点下第 N 级及更深目录清空内部内容。
- 路径深度由规范化后的挂载点相对路径计算。
- 后端将 `delete_min_depth` 随目录结果返回；前端按钮显隐和后端执行校验使用同一个值。

### 9.2 本机

- 使用 `resolve(strict=True)` 解析挂载点和目标路径。
- 再次校验目标在挂载点内且是目录。
- 递归删除目标内部条目，保留目标目录本身。
- 不跟随符号链接。
- 检测设备号，不跨越其他挂载点。

### 9.3 远程

- 使用 `readlink -f` 和 shell `case` 再次校验路径。
- 通过 `find "$target" -xdev -mindepth 1 -depth -print0 -delete` 删除内部内容。
- 总超时 60 秒。
- 目标目录本身因为 `-mindepth 1` 被保留。

### 9.4 完成后

- 使该机器目录缓存和在途目录任务失效。
- 约 350 ms 后刷新该机器快照。
- 前端重新读取父目录和文件系统数据。

## 10. 终止进程

### 10.1 开关

默认关闭，必须使用 `--allow-kill`。

### 10.2 本机

调用：

```python
os.kill(pid, signal.SIGTERM)
```

### 10.3 远程

执行固定 SSH 参数：

```text
kill -TERM -- <整数 PID>
```

总超时 8 秒。

### 10.4 保护与限制

- PID 必须大于 1。
- 拒绝终止当前监视器进程。
- 操作受运行账户或 SSH 账户的系统权限约束。
- 成功发出信号后立即从每机缓存移除该 PID，并异步刷新。
- 当前实现没有额外保护进程名单，也没有在终止前复核进程启动时间；这属于明确的现有限制。

## 11. 反向 SSH 隧道地址识别

只对 `local=false` 且地址为 `127.x.x.x`、`localhost` 或 `::1` 的机器尝试识别。

流程：

1. `sudo -n ss -H -ltnp` 找到配置端口对应监听 socket 的 `sshd` PID。
2. `sudo -n ss -H -tnp state established` 找到同一 PID 的已建立连接。
3. 选择全局公网 IP 作为隧道对端。
4. 结果缓存 10 分钟。
5. 识别失败则返回空值，前端显示回环地址和端口。

本机配置和普通非回环 SSH 地址直接跳过，不执行 `sudo ss`，因此不会影响正常 SSH 地址展示。
需要识别隧道公网对端时，运行账户必须能够免交互执行上述 `sudo -n ss`；权限不满足只会放弃地址识别，不影响通过配置端口执行普通 SSH 采集。

## 12. HTTP API

### 12.1 页面与状态

| 方法 | 路径 | 行为 |
|---|---|---|
| `GET` | `/`、`/index.html` | 返回 `doc/index.html` 单文件前端 |
| `GET` | `/api/health` | 返回运行状态、周期和危险功能开关 |
| `GET` | `/api/hosts` | 返回机器元数据、已有缓存状态和快照周期，不触发全机采集 |
| `GET` | `/api/host-statuses` | 返回全部机器的轻量 SSH 状态缓存、30 秒周期和 75 秒有效期，不触发 SSH |
| `GET` | `/api/hosts/{id}/snapshot` | 返回该机器共享快照；过期时合并并发请求后只采集一次 |

### 12.2 机器管理

| 方法 | 路径 | 行为 |
|---|---|---|
| `POST` | `/api/hosts/test` | 测试输入的机器连接，不保存 |
| `POST` | `/api/hosts` | 验证、创建并持久化机器 |
| `PATCH` | `/api/hosts/{id}` | 重命名或修改连接 |
| `DELETE` | `/api/hosts/{id}` | 删除机器配置及其内存状态 |

### 12.3 资源与操作

| 方法 | 路径 | 行为 |
|---|---|---|
| `GET` | `/api/hosts/{id}/processes` | 兼容接口：采集指定机器并返回进程 |
| `GET` | `/api/hosts/{id}/filesystems` | 兼容接口：采集指定机器并返回文件系统 |
| `GET` | `/api/hosts/{id}/directories?mount=...&path=...` | 获取缓存、启动或轮询目录任务 |
| `POST` | `/api/hosts/{id}/directories/clear` | 清空合法目录内容 |
| `POST` | `/api/hosts/{id}/processes/{pid}/terminate` | 发送 SIGTERM |
| `GET` | `/api/snapshots` | 兼容接口：只返回已在内存中的机器快照，不触发采集 |

所有 JSON 响应使用 `Cache-Control: no-store`。响应体达到 1024 字节且客户端接受 gzip 时，使用 gzip level 5 压缩。

## 13. 前端实现

- 原生 HTML、CSS 和 JavaScript，无框架、构建工具或外部资源。
- 通过 `file://` 直接打开时启用页面内存中的模拟 API，提供三台机器、动态进程、目录树和操作反馈；通过 HTTP/HTTPS 打开时只调用真实后端，不混入模拟数据。
- 使用系统字体栈和 `font-variant-numeric: tabular-nums`。
- 机器、资源、排序、目录和弹窗状态统一保存在一个页面级 `state` 对象中。
- 每个机器 Tab 渲染 `connectivity_status`，浏览器每 30 秒读取 `/api/host-statuses` 后只更新状态点。
- CPU/内存采集时间前渲染 `collection_status`；该字段只随当前机器快照更新。
- 两类状态点复用颜色和动画样式，但字段、接口、更新周期和可访问名称完全独立。
- 资源摘要使用四列紧凑固定栅格且无分隔线；同一资源页刷新只更新数值节点。
- 排序使用稳定的数值或本地化字符串比较。
- CPU/内存刷新前记录旧行位置和指纹；刷新后使用 FLIP 位移动画和轻量背景动画。
- 硬盘表格不参加该动画和周期重建。
- 采集时间每秒只更新文本；冒号使用 CSS 动画。
- 媒体查询在窄屏隐藏次要列并保留核心操作。
- `prefers-reduced-motion` 下关闭非必要动画。

## 14. 并发与线程

- HTTP 层：`ThreadingHTTPServer`，每个请求可独立处理。
- 快照层：每机一个采集锁；同机并发请求 single-flight 合并，不同机器仍可并行。
- 维护线程：只清理过期目录和隧道缓存，不采集机器。
- 主机健康线程：每 30 秒调度一次；单轮最多八个并行 `ssh ... true`，首次失败 3 秒后复查。
- 目录任务：每个未命中目录一个后台线程。
- 目录内部：最多四个 `du` 工作线程或远程 `xargs -P 4`。
- 终止进程和清空目录后：递增该机器快照代次、立即标记过期，再由一个延迟刷新线程进入同一采集锁。
- 共享状态由 `threading.RLock` 保护。

当前没有全局“活跃机器”状态；“只采集当前机器资源”由每个浏览器页面只请求自身当前 Tab 保证。全机 SSH 健康检查只判断连通性，不读取 CPU、内存、硬盘或进程。

## 15. 认证与网络安全

### 15.1 Web 认证

- 使用 HTTP Basic Authentication。
- 通过 `MONITOR_USERNAME`、`MONITOR_PASSWORD` 或对应命令行参数配置。
- 浏览器弹出的用户名密码框由 HTTP 401 和 `WWW-Authenticate` 触发。
- 认证信息不写入 `hosts.json`。

### 15.2 监听与域名

- 默认监听 `127.0.0.1:8080`。
- 绑定 `0.0.0.0` 或其他非本机地址时必须同时配置用户名和密码。
- 程序只提供明文 HTTP，不包含 TLS。
- 域名公网访问建议由 Caddy/Nginx 提供 HTTPS，再反向代理到回环地址；可信 VPN 也可使用。
- 直接暴露公网端口虽然可运行，但 Basic Auth 凭据和操作请求会依赖传输链路安全，不建议使用明文公网 HTTP。

### 15.3 SSH

- 使用系统 `ssh` 和运行账户已有密钥。
- `BatchMode=yes` 禁止交互式密码输入。
- 网页不接收 SSH 密码或私钥。
- 远程账户权限直接决定可读取目录、终止进程和清空目录的范围。

### 15.4 当前安全边界

- 后端固定采集与操作命令，PID 强制转换为整数。
- 主机字段经过格式校验。
- 目录路径经过规范化、真实路径和挂载点边界校验。
- 危险能力默认关闭。
- 当前实现没有 CSRF Token、Origin 校验、细粒度角色、持久化审计日志或 TLS；部署时必须通过可信网络和访问控制补足。

## 16. 数据持久化

| 数据 | 位置 | 生命周期 |
|---|---|---|
| 机器配置 | `--hosts` 指定文件，或优先 `hosts.local.json`、其次 `hosts.json` | 持久化，原子更新 |
| 每机最新快照、单调采集时间和采集锁 | Python 内存 | 每个周期最多实际采集一次；删除机器时快照失效，轻量同步对象随进程生命周期存在 |
| 每机 SSH 健康状态 | Python KV 内存 | 持续覆盖；75 秒未更新对外变黄；删除机器或进程重启时清除 |
| 目录结果 | Python KV 内存 | 10 分钟或主动失效 |
| 隧道公网对端 | Python KV 内存 | 10 分钟 |
| 浏览器快照与树 | 页面内存 | 页面刷新或关闭 |

没有 SQLite、历史表、快照文件或前端本地持久化。

## 17. 部署与运行规模

推荐：

```text
Internet / LAN
      │ HTTPS
      ▼
Caddy / Nginx / VPN
      │ http://127.0.0.1:8080
      ▼
monitor.py
```

长期运行建议交给 systemd；临时验证可以直接在终端运行。完整命令见 `../README.md`。

### 17.1 参考资源占用

当前实现没有历史数据堆积，常驻资源主要来自 Python 解释器、机器配置、每机最新快照和线程对象。现有版本的参考测量：

- 两台机器各保留一份约 100 KB 快照时，`monitor.py` 常驻 RSS 约 29 MB，空闲 CPU 接近 0%。
- 增加到 10 台常规 Linux 机器时，通常约 30–35 MB 常驻内存；实际值取决于进程数量、线程栈、Python 版本和系统分配器。
- 周期采集会短暂启动 `ssh`、`ps`、`df` 等子进程，不会形成常驻采集进程。
- `du` 递归目录统计是最可能产生明显磁盘 I/O 的操作，因此只在点击目录时执行，并复用 10 分钟内存缓存。
- 机器配置是唯一业务持久化数据；运行时不会持续增长快照文件或历史数据库。

这些数据用于估算小规模部署，不是硬性容量保证。机器进程数、并发目录扫描或浏览器访问规模显著增加时，应重新压测。

### 17.2 变更生效

- 修改机器配置可通过页面立即生效，无需重启。
- 修改 `monitor.py` 后必须重启 Python 进程。
- 修改 `doc/index.html` 后，现有服务会在下一次页面请求时读取新文件；浏览器若恢复旧会话或缓存，应执行一次强制刷新。
- `hosts.local.json` 优先于仓库中的脱敏 `hosts.json`，真实机器信息不应提交到 Git。

## 19. 明确限制与升级边界

- 无历史趋势、告警、报表和容量预测。
- 无 Agent、容器指标、日志和 APM。
- 无多用户角色与完整审计。

- 无内置 HTTPS。
- 不适合不受信任的多租户环境。
